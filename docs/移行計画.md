# V1 → V2 移行計画

作成日: 2026-07-23 ／ 実行日: 切替日（未定）

## 方針

- 移行スクリプトは `supabase/migrations/900_migrate_from_v1.sql`（1トランザクション・件数検証つき・失敗時は全ロールバック）
- V1のテーブル・データは**一切変更しない**（切替後もしばらく読み取り可能な保険として残す）
- 書類ファイルは同じstorageバケットを使うため**コピー不要**（DB上の参照先だけ張り替え）

## 移行対象と変換

| V1 | → V2 | 備考 |
|---|---|---|
| agencies | companies（全社Aライン） | 企業コードを参加日順に `A00001`〜 自動採番 |
| referrals | candidates（stage=screening）＋経路履歴2行を合成 | 選考ステータスはそのまま引き継ぎ |
| intake（確認待ち） | candidates（stage=relay・KANOA判断待ち） | |
| projects / assignments | projects_v2 / project_shares | |
| messages | messages_v2 | kanoa→up／agency→self に読み替え |
| invoices / documents / tasks | 同名_v2 | |
| pw_hash | legacy_pw_hash | 初回ログイン成功時に自動で強い方式(bcrypt)へ再ハッシュ。**パートナーの作業ゼロ** |

## ⚠ パートナーへの案内が必要な変更点

1. **ログインIDが「メールアドレス」→「企業コード」に変わる**
   - 切替時に各社へ「あなたの企業コードは A000XX です」の案内が必要
   - 案内文はV2の一斉連絡…はログイン前なので使えない → **切替前にV1のチャットで案内**、またはメールで通知
2. パスワードは今までのものがそのまま使える（変更不要）
3. URLが変わる場合は新URLも同時に案内

## 切替手順（切替日）

1. V1をメンテナンス表示に（読み取り専用化）
2. `900_migrate_from_v1.sql` を実行（BEGIN〜検証まで）
3. 検証結果の件数が全行一致 → COMMIT／不一致 → ROLLBACK して原因調査
4. V2で動作確認（管理者ログイン・パートナー1社でログイン・候補者一覧・チャット履歴）
5. テストデータ（A99998 / A99999 / B00001 / テスト太郎）を削除
6. パートナー各社へ企業コードと新URLを案内
7. V1はしばらく残す（1ヶ月目安）→ 問題なければアーカイブ
